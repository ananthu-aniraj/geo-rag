# Geo-RAG Evaluation Metrics Methodology

This document provides a mathematical and conceptual breakdown of the evaluation and retrieval benchmarking metrics used across the Geo-RAG suites.

---

## 📊 Summary of Metrics Across Suites

The following table summarizes the overlapping metrics used throughout the different benchmarking modules:

| Metric | Type | Mathematical Definition | Used In | Purpose |
|---|---|---|---|---|
| **Precision@K (P@1 / @5 / @10)** | Retrieval | $\frac{1}{K} \sum_{i=1}^{K} \mathbb{I}(l\_i == l\_{\text{query}})$ | `benchmark_lucas.py`, `benchmark_places.py`, `benchmark_eunis.py`, `benchmark_environmental_zones.py` | Measures what fraction of top-*K* retrieved database items belong to the query class. |

| **MRR@10** | Retrieval | $\frac{1}{N} \sum_{q=1}^{N} \frac{1}{\text{rank}\_q}$ | `benchmark_lucas.py`, `benchmark_places.py`, `benchmark_eunis.py`, `benchmark_environmental_zones.py` | Evaluates the reciprocal rank of the first relevant class match in the retrieved list. |

## 🔎 Detailed Metrics Breakdown

### 1. Spatial-Semantic Retrieval Metrics

These metrics are used to compare the representation capabilities of different pooling strategies (such as visual CLS tokens, global average patch pooling, and foreground Seg-Masked embeddings) under K-Nearest Neighbor retrieval.

#### A. Precision@K (P@K)

Precision at *K* measures the proportion of retrieved items in the Top-*K* list that share the exact ground-truth label as the query image.

$$
\text{Precision@K} = \frac{1}{K} \sum_{i=1}^{K} \mathbb{I}(\text{Class}(\text{Result}_i) == \text{Class}(\text{Query}))
$$

* **P@1:** Measures the exact nearest-neighbor class match.
* **P@5 / P@10:** Measures local category density and robustness to outliers within the top retrieval neighborhood.

#### B. Mean Average Precision @ 10 (mAP@10)

Mean Average Precision measures retrieval precision while factoring in the rank position of relevant items. Average Precision (AP) for a single query *q* is defined as:

$$
\text{AP@10}(q) = \frac{1}{\min(R, 10)} \sum_{i=1}^{10} \text{Precision}(i) \times \mathbb{I}(\text{Class}(\text{Result}_i) == \text{Class}(\text{Query}))
$$

where:

* **Precision(*i*)** is the Precision@*i* calculated on the sublist up to rank *i*.
* *R* is the total number of relevant matches in the database.
* **I(·)** is an indicator function.

The overall benchmark reports **mAP@10**, which is the average of **AP@10(*q*)** across all evaluated queries:

$$
\text{mAP@10} = \frac{1}{N} \sum_{q=1}^{N} \text{AP@10}(q)
$$

#### C. Mean Reciprocal Rank (MRR@10)

Mean Reciprocal Rank measures how quickly the retrieval system returns the *first* correct match. For a query *q*, let **rank_*q*** be the rank position (1-indexed) of the first correct class match. The reciprocal rank is **1 / rank_*q***. If no correct match exists in the top-10 list, the reciprocal rank is 0.

$$
\text{MRR@10} = \frac{1}{N} \sum_{q=1}^{N} \frac{1}{\text{rank}_q}
$$

* **Example:** If the first correct class match is at rank 3, the Reciprocal Rank is $1/3 \approx 0.33$. If it is at rank 1, the Reciprocal Rank is 1.0.

### 2. Zero-Shot Captioning & Semantic Mapping Metrics

These metrics are used to validate the quality of captions generated by Vision-Language Models (VLMs) and evaluate zero-shot scene parsing accuracy.

#### A. Semantic Embedding Cosine Similarity

To evaluate whether a free-form text prediction maps correctly to structured taxonomy classes (like Places365 or LUCAS classes) without relying on strict keyword parsing:

1. The VLM generated text prediction and the ground-truth class name are embedded using a text-encoder (e.g. `all-MiniLM-L6-v2`).
2. The cosine similarity of their vector representations **u** and **v** is computed:

$$
\text{Similarity}(\vec{u}, \vec{v}) = \frac{\vec{u} \cdot \vec{v}}{\|\vec{u}\|_2 \|\vec{v}\|_2}
$$

* **Interpretation:** A score of 1.0 indicates perfect semantic equivalence. A higher threshold (e.g., $>0.75$) indicates a strong conceptual match (e.g. *"forest road"* vs. *"woodland path"*).

#### B. Visual Alignment Cosine Similarity

Evaluates the mutual information between the generated caption string and the source image.

1. The raw image is embedded using the image tower of a contrastively aligned model (like CLIP or TIPSv2).
2. The VLM caption is embedded using the corresponding text tower.
3. The cosine similarity between the image vector and the text vector is computed.

---

### 3. Overlap & Unification Opportunities

To ensure consistency and ease of maintenance across the codebase, the following designs have been unified:

1. **Shared Retrieval Logic:** All four benchmarking scripts (`benchmark_lucas.py`, `benchmark_places.py`, `benchmark_eunis.py`, `benchmark_environmental_zones.py`) share the same KNN retrieval metrics implementation (relying on cosine similarity and matrix multiplication).
2. **Standardized Coordinate Projectors:** Geographic raster lookups use the same coordinate transformation pipelines, allowing seamless cross-module testing.
